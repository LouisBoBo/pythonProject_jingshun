# Skill Optimizer

对已有的 SKILL.md 进行结构分析和重写优化，基于 LLM 注意力模型（U 型曲线）和 token 效率原则。

---

## ⚠️ 核心原理：LLM 注意力 U 型曲线（Lost in the Middle）

LLM 对 prompt 的注意力分布呈 **U 型**：**开头和结尾关注度最高，中间部分容易被忽略。**

```
注意力
  ↑
高 █                                         █
  │  █                                     █
  │     █                               █
  │        █                         █
低 │           █ ─ ─ ─ ─ ─ ─ ─ ─ █
  └──────────────────────────────────────→ 位置
    开头        中间（盲区）         结尾
```

**这意味着：放在 SKILL.md 中间的规则，AI 最容易违反。**

---

## 执行流程

当用户要求优化某个 SKILL 时，按以下步骤执行：

### Step 1：读取目标 SKILL.md

读取完整文件，记录总行数。

### Step 2：逐项检查（7 条审计规则）

对照以下 7 条规则逐一检查，输出审计报告表格：

| # | 规则 | 检查方法 | 严重度 |
|---|------|---------|--------|
| 1 | **关键约束被埋中间** | 找出"必须"、"禁止"、"不允许"等强制性规则，检查它们是否在文件前 20% 或后 20% | 🔴 高 |
| 2 | **开头放了低价值内容** | 检查前 15 行是否被触发关键词、目录、文件结构等非行为性内容占据 | 🔴 高 |
| 3 | **长平铺列表（>8 条）** | 找出连续 bullet/numbered list 超过 8 条的段落 | 🟡 中 |
| 4 | **内容重复** | 找出语义重复的段落（同一信息出现 2 次以上） | 🟡 中 |
| 5 | **指令含糊不可执行** | 找出缺少具体命令/路径/参数的操作步骤 | 🟡 中 |
| 6 | **token 浪费** | 找出可压缩的冗长描述、多余示例、重复解释 | 🟢 低 |
| 7 | **缺少失败处理** | 检查操作步骤是否有"如果失败则…"的分支 | 🟢 低 |

### Step 3：输出审计报告

格式：

```markdown
## SKILL 审计报告：<skill-name>

**总行数**：XXX 行
**发现问题**：X 项

| # | 规则 | 状态 | 问题描述 | 位置（行号）|
|---|------|------|---------|-----------|
| 1 | 关键约束被埋中间 | 🔴 | ... | L120-L180 |
| 2 | 开头低价值内容 | ✅ | 无问题 | — |
| ... |

### 建议重构方案
1. ...
2. ...
```

### Step 4：确认后重写

**等用户确认后**，执行重写。重写必须遵循以下结构模板：

```
1. YAML frontmatter（name + description）
2. 一句话概述
3. ⚠️ 关键约束（必须/禁止/强制规则）     ← 开头黄金位置
4. 核心工作规则（查阅/更新/检查等）
5. 指令/流程（commit/pr 等操作步骤）
6. 参考信息（速查表/触发关键词等）         ← 结尾次黄金位置
```

## 重写原则

### 原则 1：位置决定权重

| 位置 | 应放置 | 不应放置 |
|------|--------|---------|
| 前 20%（开头） | 强制约束、禁止事项、必须执行的规则 | 触发关键词、文件结构、目录索引 |
| 中间 60% | 常规工作流、查阅规则、更新规则 | 最重要的行为约束 |
| 后 20%（结尾） | 指令步骤、参考速查表 | 无关紧要的说明 |

### 原则 2：压缩而非删除

- 长列表（>8 条）→ 合并为表格或分类小组（每组 ≤5 条）
- 重复内容 → 保留一处，删除其余
- 冗长解释 → 一句话 + 示例
- 多种备选方案 → 只写推荐方案，备选用括号一笔带过

### 原则 3：可执行性

每条操作步骤必须包含：
- **具体命令**或**工具名称**
- **成功标准**（怎么判断做完了）
- **失败处理**（如果不行怎么办）

❌ "检查代码质量" → ✅ "执行 `npm run lint:web`，0 errors 才继续，有 error 则修复（最多 3 轮）"

### 原则 4：Token 预算

| Skill 类型 | 目标行数 |
|-----------|---------|
| 轻量规则型 | < 80 行 |
| 领域专家型 | < 150 行 |
| 包含指令的复合型 | < 200 行 |

超出预算时优先砍：示例 > 解释 > 备选方案 > 表格行数。

## 常见问题速查

| 症状 | 对应规则 | 修复方法 |
|------|---------|---------|
| AI 总是忘记跑 lint | #1 关键约束被埋 | 把 lint 规则移到开头 |
| AI 漏掉报告中的某几项要求 | #3 长平铺列表 | 拆分为分组或表格 |
| AI 用了错误的命令/路径 | #5 指令含糊 | 补全具体命令和参数 |
| SKILL 太长导致 AI 跳过中间内容 | #6 token 浪费 | 压缩重复、删冗余 |
| 同一信息写了两遍 | #4 内容重复 | 合并为一处 |
