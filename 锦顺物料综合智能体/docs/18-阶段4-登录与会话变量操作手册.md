## 总览：设计原则（被动登录）

**不要**让用户一上来就说「我要登录」——用户正常查数、问领料即可；**只有触碰到需要 ERP 身份的能力时**，才自然提示验证。

| 原则 | 说明 |
|------|------|
| 查数 / 寒暄 | **永不**要求登录，与 3.5 相同 |
| 领料 / 混合 | 未登录 → **友好提示** + 等待用户回复工号密码 |
| 登录触发 | 用户**自然回复凭据**时走登录链，**不强制**「登录 xxx xxx」口令 |
| 已登录 | 同一会话内 token 持久，不再重复问 |

| 项 | 阶段 3.5 | 阶段 4（本阶段） |
|----|----------|------------------|
| 会话变量 | 3 个查数变量 | + `auth_token` / `user_profile` / `login_pending` |
| 入口 | 直接 → 分类器 | Code 路由：**领料→prompt** / **有凭据→authenticate** / 否则→分类器 |
| Agent 前 | 直接进 Agent | **兜底**拦截（Code 未识别的 REQUISITION） |
| 登录执行 | — | Code 直出 username/password → HTTP（Extractor 备选） |

## 步骤 2：画布拓扑（被动登录）

```
用户输入
  → Code「登录路由」→ should_login / login_action / reason
  → If-Else should_login == "true"
      ├─ login_action == "authenticate" → 提取凭据 → HTTP → Assigner → Login Answer
      ├─ login_action == "prompt"       → Assigner(login_pending) → 自然提示（无 Extractor）
      └─ false → Code「领料/查单路由」（见 §查单路由）
            ├─ use_agent == true → Agent 链（已登录兜底）
            └─ false → 意图分类器 → …
```

> **没有**「用户一开口就必须登录」的分支。  
> **查数 DATA / 寒暄 CHITCHAT** 永远不检查登录。

### 对话状态机

```
[未登录] ──领料/混合──→ 提示验证 ──login_pending=true──→ [等待凭据]
                              ↑                              │
                              │         用户回复工号密码        │
                              └──────── should_login ────────┘
                                        ↓
                                   登录成功 → login_pending 清空
```

## 步骤 4：登录链（两条子路径 · 约 25 分钟）

> **关键**：`should_login = "true"` **不等于**一定要 Parameter Extractor。  
> 看上游 Code 的 **`login_action`**：
>
> | login_action | 何时 | 做什么 |
> |--------------|------|--------|
> | **`prompt`** | `我要领料` 等，**句中无工号密码** | **只提示**验证身份 + 写 `login_pending`，**不**调 Extractor |
> | **`authenticate`** | `zhangsan 123456`、`登录 zhangsan 123456` | Parameter Extractor → HTTP 登录 |

### 4.0 登录链入口 If-Else（在 should_login=true 之后）

**条件**：登录路由 / `login_action` **等于** `authenticate`

| 出口 | 去向 |
|------|------|
| **true** | → §4.1 提取凭据 → HTTP 登录 |
| **false**（`login_action` = `prompt`） | → §4.8 仅提示（**跳过 Extractor**） |

```
should_login = true
  → If-Else login_action == authenticate ?
      ├─ true  → Extractor → HTTP → 解析 → Assigner → Login Answer
      └─ false → Assigner(login_pending) → 自然提示 Answer
```

---

### 4.1 凭据来源（推荐：Code 直出，少一层 LLM）

登录路由 Code 在 `login_action=authenticate` 时会同时输出 **`username`**、**`password`**。

**推荐路径（稳定 · 防 422）**：

```
If login_action == authenticate
  → Code「组装登录Body」build_erp_login_body.py
  → HTTP 登录（Body 选 raw，绑 body_json）
```

> **不要**在 HTTP 节点里直接写 `"password": {{#登录路由.password#}}`（无引号）——  
> Dify 会把 `123456` 插成 JSON **数字**，Mock 返回 422：`password should be a valid string`。

**Code「组装登录Body」** [`build_erp_login_body.py`](../workflows/code/build_erp_login_body.py)

| 输入 | 来源 |
|------|------|
| username | 登录路由 / username |
| password | 登录路由 / password |

| 输出 | 用途 |
|------|------|
| body_json | HTTP Body（整段 JSON 字符串） |

**HTTP 节点 Body 配置**：

| 项 | 值 |
|----|-----|
| Body 类型 | **raw** / 文本（或 JSON，绑变量字段） |
| 内容 | `{{#组装登录Body.body_json#}}` |

正确发出应为：

```json
{"username": "zhangsan", "password": "123456"}
```

注意 `password` 两侧有引号。

**备选（仅当坚持用 HTTP 可视化 JSON 编辑器时）**：

```json
{
  "username": "{{#登录路由.username#}}",
  "password": "{{#登录路由.password#}}"
}
```

`password` 值**必须**写在双引号内；若仍变成数字，改用上方的 `build_erp_login_body`。

### 4.2 Parameter Extractor（备选 · 仅 Code 未出凭据时）

**何时才需要**：`login_action=authenticate` 且 Code 的 `username` 为空（少见）。

| 项 | 值 |
|----|-----|
| Instruction | [`prompts/登录参数提取器-阶段4.md`](../prompts/登录参数提取器-阶段4.md) |

**禁止**：在 `login_action=prompt`（如 `我要领料`）后接 Extractor。

### 4.3 If-Else「凭据是否齐全？」

| 条件 | 出口 |
|------|------|
| username 不为空 **且** password 不为空 | → HTTP 登录 |
| ELSE | → 提取失败 Answer |

**提取失败 Answer**（仅 authenticate 仍缺字段时）：

```markdown
没有识别到工号和密码，请再发一次，例如：

zhangsan 123456
```

### 4.4 HTTP Request「ERP 登录」

| 项 | 值 |
|----|-----|
| 方法 | POST |
| URL | `https://a4d5-218-95-67-64.ngrok-free.app/api/auth/login` |
| 连接/读取超时 | 30 / 60 |

**Body**：绑 **`组装登录Body.body_json`**（见 §4.1），勿用无引号的 password 插值。

**Headers**（检查勿拼错 `Content-Type`）

**失败处理**：HTTP 节点勾选「失败时继续」或下游 Code 读 `status_code`。

### 4.5 Code「解析登录」

全量粘贴 [`workflows/code/parse_erp_login_response.py`](../workflows/code/parse_erp_login_response.py)（`import` 到 `return`）。

**输入绑定**：

| 输入变量 | 来源 |
|----------|------|
| `body` | HTTP 登录 / body（或 text，以运行日志为准） |
| `status_code` | HTTP 登录 / status_code |

**输出变量**：

| 输出 | 类型 |
|------|------|
| `auth_token` | string |
| `token_expires_at` | string |
| `user_profile` | object |
| `login_ok` | **string** `"true"` / `"false"` |
| `login_message` | string |

### 4.6 If-Else「登录是否成功？」

| 条件 | 出口 |
|------|------|
| 解析登录 / `login_ok` **等于** `true`（**字符串**） | → Assigner |
| ELSE | → Login Answer |

### 4.7 Variable Assigner「写入登录态」

| 变量 | 值 | 操作 |
|------|-----|------|
| `conversation.auth_token` | 解析登录 / auth_token | Overwrite |
| `conversation.token_expires_at` | 解析登录 / token_expires_at | Overwrite |
| `conversation.user_profile` | 解析登录 / user_profile | Overwrite |
| `conversation.login_pending` | 空字符串 `""` 或 `false` | Overwrite |

### 4.8 直接回复「Login Answer」

成功时建议在 `login_message` 后补一句衔接（可在 Code 或 Answer 模板写）：

```
{{#解析登录.login_message#}}

您可以说出要领的物料，例如：帮我领 10KG 阻焊油墨。
```

### 4.9 仅提示路径（login_action = prompt）

**何时**：用户说 `我要领料`、`帮我领10KG油墨` 等，触登录但 **句中无凭据**。

**Variable Assigner「标记等待登录」**

| 变量 | 值 | 操作 |
|------|-----|------|
| `conversation.login_pending` | `true` | Overwrite |

**直接回复「需要验证身份」**（与步骤 5.3 相同文案）：

```markdown
办理领料、查 ERP 库存或提交申请前，需要先验证您的 ERP 身份。

请**直接回复工号和密码**（一句即可），例如：

zhangsan 123456

（数据统计类问题无需登录，您仍可随时问我「统计2025年各月消耗」等。）
```

> 用户下一句发 `zhangsan 123456` 时，Code 返回 `login_action=authenticate`，才进入 §4.1 Extractor。

- [ ] **authenticate** 路径：Extractor → HTTP → Assigner 已连通

## 常见问题

| Key | Value |
|-----|-------|
| Content-Type | application/json |
| ngrok-skip-browser-warning | true |

> ngrok 子域变化时 **只改 URL 前缀**。

**Q：HTTP 422，password should be a valid string**  
A：Body 里 password 被发成数字 `123456` 而非 `"123456"`。用 [`build_erp_login_body.py`](../workflows/code/build_erp_login_body.py) 组装 Body，或 JSON 模板里 password 必须加双引号。

**Q：登录 HTTP 502 / timeout**  
A：Mock 或 ngrok 已停；重启 `./run.sh` + `ngrok http 8900`，同步改 HTTP URL。

**Q：登录 HTTP 200 但返回 HTML**  
A：缺少 Header `ngrok-skip-browser-warning: true`。

**Q：登录成功但 Assigner 未写入**  
A：查 If-Else `login_ok` 分支是否接到 Assigner；Assigner 变量名是否为 `conversation.auth_token`。

**Q：用户必须说「我要登录」吗？**  
A：**不需要**。领料时自然提示；用户回复 `zhangsan 123456` 即可。`登录 xxx xxx` 仅作兼容。

**Q：「登录后怎么查数」误进登录链？**  
A：被动登录方案下 **不会**（无凭据、非 pending → 走分类器 → DATA）。

**Q：用户只回「好的」？**  
A：不会进登录链；可再次说明需要工号密码，或用户下一句发凭据。

**Q：查数变慢或走错路**  
A：确认 false 出口接分类器；DATA 分支未插入登录 HTTP。

**Q：已登录仍提示未登录**  
A：Assigner 是否 Overwrite；是否开了新会话（conversation 变量不跨会话）。

**Q：Custom Tool 能否自动读 conversation.auth_token？**  
A：Dify 1.13 Custom Tool **通常不能**在 Header 里绑 conversation 变量；阶段 5 由 **Agent 调 Tool 时传 token 参数**，或 Tool 描述要求 Agent 填 Authorization。
