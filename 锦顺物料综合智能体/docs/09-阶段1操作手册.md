## 步骤 1.2 增加 Tool 入参 `question`（约 15 分钟）

### 1.2.1 在「用户输入」节点增加变量

1. 点击画布最左侧 **用户输入** 节点  
2. **输入字段** → **添加变量**：

| 字段名 | 类型 | 必填 | 标签（显示名） |
|--------|------|------|----------------|
| `question` | 短文本 Short Text | 是 | 用户问题 |

3. 保存节点  

> 发布后作为 Tool 时，Agent 只会传入 Start 上声明的变量；**必须有 `question`**。

### 1.2.2 增加「归一化用户问题」Code 节点（推荐）

Tool 调用走 `question`；你在预览里直接聊天走 `sys.query`。用一个 Code 节点合并两者，避免改十几个 LLM 节点。

1. 在 **用户输入** 与 **问题分类器** 之间插入 **Code** 节点  
2. 节点标题：`归一化用户问题`  
3. 输入变量：

| 变量名 | 来源 |
|--------|------|
| `question` | 用户输入 / `question` |
| `sys_query` | 系统变量 / `sys.query` |

4. 代码：

```python
def main(question: str = "", sys_query: str = "") -> dict:
    q = (question or sys_query or "").strip()
    return {"user_question": q}
```

5. 输出变量：`user_question`（string）

6. **连线调整**：
   - 原：用户输入 → 问题分类器  
   - 新：用户输入 → **归一化用户问题** → 问题分类器  

- [ ] Code 节点已添加并连线

## 步骤 1.3 替换各节点中的「当前用户问题」引用（约 20～30 分钟）

以下节点里，凡引用 **`sys.query`** 或 **`用户输入.query`** 表示「当前用户本轮问题」的，改为：

```text
{{#归一化用户问题.user_question#}}
```

（变量选择器里选 Code 节点输出的 `user_question`；节点标题若不同，按实际名称选。）

### 必须修改的节点清单

| 序号 | 画布节点名称 | 改什么 |
|------|--------------|--------|
| 1 | **问题分类器** | System 里 `{{#1=用户输入.query}}` → `user_question`；User 里 `{{#sys.query#}}` → `user_question` |
| 2 | **判断历史数据是否可以回复用户问题** | `当前用户问题` 处的 `{{#sys.query#}}` |
| 3 | **生成新的问题查询** | `本轮追问：{{{#sys.query#}}}` → `user_question` |
| 4 | **生成SQL语句** | User 消息里若有 `sys.query`，改为 `user_question`（若上游已是合并后问题则保持） |
| 5 | **数据分析**（主分析 LLM，连 Answer 那条） | User 里的 `{{#sys.query#}}` |
| 6 | **数据分析**（明细表那条，若单独存在） | 同上 |
| 7 | **判断是否图表及生成图表标题** | 含 `sys.query` 的 prompt |
| 8 | **参数提取器** | Query 来源若绑的是 sys.query，改为 `user_question` |

### 不要改的引用

| 节点/变量 | 原因 |
|-----------|------|
| `conversation.last_query` | 上一轮问题，追问合并用 |
| `conversation.origan_data_records` | 历史数据 |
| `conversation.data_records` | 处理后数据 |
| **保存用户初始问题** Assigner | 仍写 `sys.query` 或改为 `user_question` 均可；建议改为 `user_question` 与合并逻辑一致 |

### 问题分类器 Memory（若有）

若 **问题分类器** 节点 Memory 里 `query_prompt_template` 仍是 `{{#sys.query#}}`，改为 `{{#归一化用户问题.user_question#}}`。

- [ ] 上表节点已全部替换  
- [ ] 保存画布

| 项 | 值 |
|----|-----|

| Tool 描述 | 见下方 |
| 入参 | 仅 `question`（string，必填） |

**Tool 描述（复制到 Dify）**：

```text
查询锦顺物料 SQL Server 数据库：统计、排名、库存、采购、出入库、用量分析，并返回 Markdown 表格与图表。
当用户问统计/查询/多少/排名/占比/趋势/明细/库存时使用。
```

## 常见问题

**Q：预览只填 question 不聊天，没反应？**  
A：确保已加「归一化用户问题」Code 节点，且下游用 `user_question`。

**Q：Tool 测试 question 有值，但 SQL 为空？**  
A：检查「生成SQL语句」LLM 的 User 是否仍引用 `sys.query` 而未改。

**Q：Publish as Tool 后找不到？**  
A：在工作区 **Tools** 页查看；需先 Publish Update 再 Publish as Tool。

**Q：追问在 Tool 模式下是否有效？**  
A：同一 Chatflow 会话内有效；主 Agent 多次调 Tool 时，由主 Agent 合并问题传入 `question`，子流程内追问逻辑在「用户直连子 Chatflow」时最完整。阶段 6 再优化主 Agent 追问。
