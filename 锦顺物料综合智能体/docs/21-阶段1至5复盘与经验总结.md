> **状态**：2026-06，阶段 1～5 **主要功能已验收**；阶段 6 及以后 **暂缓**，先稳再扩。

## 一、做得好的地方（可复用）

### 1. 混合编排架构

| 模式 | 适用 | 复用要点 |
|------|------|----------|
| **Fast 路径** | 查数、统计、明细、追问 | HTTP → 子 Chatflow API；`conversation_id` 子会话传递；Answer 只绑 `last_query_detail` |
| **Agent 路径** | 领料、GON 查单、MIXED | Tool 链 + Instruction；Function Calling 减少过程外泄 |
| **短 LLM** | 寒暄 | 不挂 Tool，低成本 |

**文档**：[17-主助手路由与传参一览.md](17-主助手路由与传参一览.md) 一张总图即可 onboarding。

### 2. 确定性 Code 节点 + LLM 分类器双保险

| Code 节点 | 作用 |
|-----------|------|
| `detect_login_route.py` | 被动登录：领料/GON 才要登录，查数永远不登录 |
| `detect_requisition_route.py` | 领料/GON/确认提交 **不进 Fast 查数** |
| `build_erp_login_body.py` | password 必须是 JSON 字符串，防 422 |
| `parse_erp_login_response.py` | 统一 `login_ok` 为 string，供 If-Else |
| `parse_sse_and_split.py` | Fast 路径解析子助手 SSE |

**经验**：LLM 分类器管「大类」；**关键词/GON/帮我领** 用 Code 拦截，避免「查询 GON」进 Text2SQL。

### 3. Agent + Custom Tool 分工清晰

- **画布**：登录、路由、变量 Assigner  
- **Agent**：选 Tool、填参、读 Observation、Final Answer  
- **Tool**：OpenAPI 定义 HTTP；参数位置写死在 [20-Agent-ERP-Tool调用参数一览.md](20-Agent-ERP-Tool调用参数一览.md)

**可复用模板**：每个 erp_* Tool 一张表（Header / Query / Body / Path + 值来源）。

### 4. Mock ERP + ngrok 联调

- 内存 Mock 快速迭代；`POST /api/dev/reset-inventory` 恢复测试库存  
- ngrok Header：`ngrok-skip-browser-warning: true`  
- 发布前本地脚本：`test_detect_login_route.py`、`test_detect_requisition_route.py`

### 5. Instruction 与 Final Answer 规范

- 确认卡片 = **尚未提交**；提交成功 = **仅 GON + 状态**  
- 禁止 Thought/Tool 名/draft 过期说明进用户可见回复  
- 库存不足：展示用户原数量，**不擅自改小**

### 6. 文档分层

|------|------|
| 总清单 | 08-分步实施清单 |
| 阶段操作 | 18（登录）、19（领料）、14（混合编排） |
| 参数契约 | 20（Tool 参数）、04（ERP API） |
| Prompt | prompts/ 目录版本化（阶段3.5 / 阶段5） |

## 二、做得不好的地方（避免再踩坑）

| # | 坑 | 后果 | 以后怎么做 |
|---|-----|------|------------|
| 1 | **If-Else 用 boolean 而非 string** | 分支永远不走 | Dify Code 输出 `"true"`/`"false"`，If-Else 用「等于」 |
| 2 | **Tool 参数位置不写清** | submit 漏 Authorization → 401 | OpenAPI + doc 20 + Instruction 三处一致；改 YAML 后 **重导 Tool** |
| 3 | **OpenAPI YAML 损坏**（submit Body 缺失） | Agent schema 无 Authorization/Body | 提交前 `yaml.safe_load` 校验；Tool 测试页逐个测 |
| 4 | **只靠 LLM 分类器** | 「帮我领」「查 GON」进 DATA | Code 路由 + 分类器文案互斥描述 |
| 5 | **Agent 未调 save_draft 就出卡片** | 确认提交无 draft_id | Instruction 铁律：有 Observation 才能出卡片 |
| 6 | **draft 过期对用户说「已提交请确认」** | 体验矛盾 | 用户已确认 → 同轮重建 draft + submit，直接给单号 |
| 7 | **擅自把申请数量改成库存上限** | 用户要 10KG 卡片变 5KG | 数量必须来自用户原话 |
| 8 | **Mock 多次 submit 占满 reserved_qty** | 可用库存变 0 | 测试前 reset-inventory；seed 库存设大 |
| 9 | **password 被 Dify 插值成数字** | login 422 | 专用 Code 组装 Body |
| 10 | **每个业务搭画布 HTTP 链** | 违背 Tool 设计、难维护 | 仅 **登录** 走画布 HTTP；业务走 Agent+Tool |

**Bug 处理原则**：复现 → 定位（路由 / Tool 参 / Prompt / Mock）→ **当场修** → 补一条自测或文档；不堆到阶段 6。

## 三、不足之处与优化建议（先不改，仅记录）

| 优先级 | 不足 | 建议 | 阶段 |
|--------|------|------|------|
| P1 | `draft_id` 仅靠 Agent Observation，Mock 重启易丢 | 会话变量 `requisition_draft_id` + Instruction 注入；阶段 6 Assigner 回写 | 6 |
| P1 | MIXED 未系统验收 | 「查库存够的话领 10KG」端到端 + Instruction 段落 | 6 |
| P2 | `last_material` 未实现 | search/inventory 后 Assigner 写入，支持「上面那个料」 | 6 |
| P2 | Token 过期仅 Instruction 提示 | If-Else 比较 `token_expires_at` 或 401 清空 token 重登 | 6 |
| P2 | 确认提交纯文本，无表单 | Human Input / 表单按钮（可选，企业 UI 要求时） | 7 |
| P3 | 未导出生产 DSL 备份 | 发布里程碑导出 `workflows/锦顺物料综合助手-5.0.yml` | 随时 |
| P3 | 幂等 `idempotency_key` 靠 Agent 生成 | 可会话变量存上次 key，防连点重复单 | 6 |
| P3 | 查数与 ERP 库存口径不一致 | 文案注明「领料库存以 ERP 为准」 | 文案 |
| P4 | ngrok 子域会变 | 文档化更新 OpenAPI servers + Dify Base URL 流程 | 运维 |
| P4 | 生产 ERP 未对接 | 按 04 规范替换 Base URL，字段 diff 附录 | 上线前 |
