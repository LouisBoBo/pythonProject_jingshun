## 步骤 5：领料调用链（Fast HTTP 读 + Agent 写）

**进 Agent 前**：画布 **Fast HTTP** 查库存（与 DATA 同链，见 [15-DATA_QUERY](15-DATA_QUERY-Fast查数路径配置详解.md)）→ Assigner 写 `last_query_detail` / `requisition_available_qty` 等。

Agent **只**调 erp_*：

```
用户：帮我领 10KG 阻焊油墨
  ↓
[画布] DATA Fast（料号+库存）→ Assigner
  ↓
erp_save_draft(items=[{material_code:会话变量, quantity:10, unit:会话变量}], …)
  ↓
Final Answer：确认卡片

用户：确认提交
  ↓
erp_submit_requisition(draft_id=…, idempotency_key=uuid, Authorization=…)
  ↓
Final Answer：GON 单号 + 待审批（submit 不扣库存）
```

> 纯「查库存/统计」→ 分类器 **DATA** → **Fast HTTP** → Answer，不进 Agent。详见 [22-库存与领料数据源定稿.md](22-库存与领料数据源定稿.md)

| 卡片库存 | 以 **Fast HTTP（Text2SQL）** 为准 |
| submit | **不再** 409 库存不足、**不再** `reserved_qty` 占用 |

## 步骤 5.6：领料 DATA Fast 读链（**必做**）

> **Dify 怎么拖线、怎么绑变量** → **[23-Dify领料画布连线逐步操作.md](23-Dify领料画布连线逐步操作.md)**（逐步操作主文档）  
> 下文保留原理说明；连线细节以 23 为准。

### 5.6 一图读懂（先看这篇）

**你现在已经有两条路：**

| 用户说什么 | 走哪 | 你画布上已有的 |
|------------|------|----------------|
| 「统计2025消耗」 | **Fast HTTP** 查数据库 → 直接回复 | DATA 那条链 ✅ |
| 「帮我领10KG油墨」 | 以前：全丢给 **Agent**（又慢又乱） | Agent 节点 ✅ |

**现在要改成：领料也先走 Fast HTTP 查库存，Agent 只负责下单。**

```
【以前 · 不对】
  帮我领10KG  →  Agent（自己调 Tool 查库存 + 搜料 + 草稿 + 提交）  →  慢

【现在 · 对】
  帮我领10KG  →  DATA Fast（料号+库存一次查齐）→  写会话变量
              →  Agent 只 save_draft →  确认卡片
  确认提交    →  Agent submit → GON
```

**记住四句话：**

1. **所有物料相关读**（料号、名称、库存、统计）= **DATA Fast**，**禁止** ERP 自然语言搜料 HTTP  
2. **领料进 Agent 前**：DATA Fast **一次**查齐 **料号 + 库存**（查库存本身就能带出料号）  
3. **Agent 只写**：`save_draft` / `submit` / `get`（**3 个 Tool**）  
4. **确认提交、查 GON** → 跳过 Fast，直进 Agent

**画布上你要做的事（一句话）：**  
在 **「已登录 → Agent」** 前面，**复制一份 DATA 的 HTTP 查数链**，改几个 Code，把库存数字存进 4 个新变量，再进 Agent。

下面 5.6.0～5.6.7 是字段怎么绑；看不懂细节时，按 **5.6.2 节点清单** 从上到下拖就行。

---

> **原则**：与 DATA 同源（HTTP → 子 Chatflow Text2SQL），**在 Agent 之前**完成；Agent **只写** erp_*。  
> **详配参考**：[15-DATA_QUERY §12](15-DATA_QUERY-Fast查数路径配置详解.md#12-推荐fast-路径直连-chat-messages锦顺现网)（HTTP URL / Key / 超时与 DATA 完全一致）

### 5.6.0 拓扑（两处 Agent 入口都要接）

**入口 A** — `detect_requisition_route` → `use_agent=true` → 已登录  
**入口 B** — 意图分类器 → REQUISITION / MIXED（agent 出口）→ 已登录  

两处 **已登录 true** 之后，**先并到同一条「领料读链」**，再进 Agent：

```
已登录 true
  → Code「是否查库存」detect_requisition_need_inventory.py
  → If-Else need_fast_inventory == "true"
        ├─ true  → 【领料 Fast 读链 5.6.1～5.6.4】→ Agent
        └─ false → Agent（确认提交 / GON 查单 / 改数量 等）
```

**跳过 Fast 查库存**（`need_fast_inventory=false`）的典型句：

| 用户说 | skip_reason |
|--------|-------------|
| `确认提交` | confirm_or_cancel |
| `查询 GON20260611003 状态` | gon_number |
| `修改数量为 5KG` | modify_qty_only |
| `取消` | confirm_or_cancel |

## 常见问题

**Q：Agent 调 erp_* 返回 401**  
A：Instruction 是否注入 `auth_token`；Agent 是否传 `Authorization: Bearer …`；token 是否过期（Mock 7200s）。

**Q：用户要 10KG，卡片却显示 5KG（还没改数量）**  
A：Agent **擅自把数量改成库存上限**。Instruction 已规定：首次必须展示用户原数量；库存不足只提示改数/取消，**禁止**自动改小。换最新 [阶段5领料版](../prompts/主控Agent系统提示词-阶段5领料版.md) 场景 A。

**Q：改数量时用户看到「根据铁律…erp_save_draft…」过程说明**  
A：Final Answer 只能输出确认卡片，不能解释内部流程。换最新 Instruction；Agent 用 Function Calling；改数量须后台 `erp_save_draft` 后再出卡片。

**Q：用户改数量为 5KG 后「确认提交」仍失败，提示草稿仍是 10 KG**  
A：**Agent 只改了卡片文字，没调 `erp_save_draft` 更新 draft_id**。解决：换最新 [阶段5领料版 Instruction](../prompts/主控Agent系统提示词-阶段5领料版.md)，强调「改数量必带 draft_id 再 save_draft」。追踪日志应看到第二次 `erp_save_draft` 后再 `submit`。

**Q：Agent 不调 Tool，只口头回复**  
A：换阶段5 Instruction；检查 Tool 描述；迭代次数是否够；模型是否支持 FC。

**Q：Agent 调 submit 漏 Authorization / 丢 draft_id**  
A：查 [20-Agent-ERP-Tool调用参数一览.md](20-Agent-ERP-Tool调用参数一览.md)：submit 的 **Authorization 在 Header**，draft_id 在 **Body**；重导 OpenAPI；Tool 测试页单独测 submit；Instruction 换最新阶段5版。

**Q：用户说「确认提交」却提示「草稿过期，请再确认」**  
A：体验错误。用户已确认时，Agent 应 **后台重建 draft 并直接 submit**，Final Answer 只给 GON 单号，**不得**再出确认卡片，**不得**说「已提交请确认」。换最新 [阶段5领料版](../prompts/主控Agent系统提示词-阶段5领料版.md) 场景 C。Mock 重启后 draft 内存丢失属正常，应对用户透明。

**Q：Agent 未确认就 submit**  
A：强化 Instruction「提交前必须确认」；检查用户是否说了「确认提交」。

**Q：submit 422 / Body 格式错**  
A：同阶段4，`quantity` 等字段类型；若 Dify 插值丢引号，可增 Code 组装 Body（参考 `build_erp_login_body.py`）。

**Q：领料很慢**  
A：首次领料含 **Fast HTTP 查库存 ~18s** + Agent 4～6 步 Tool；「确认提交」跳过 Fast 只走 Agent submit。

**Q：卡片库存为空 / extract_ok=false**  
A：查 `requisition_inventory_detail` 是否有表；子 Chatflow 返回格式是否含数量；可微调 [`extract_inventory_from_detail.py`](../workflows/code/extract_inventory_from_detail.py)。Agent 可读 detail 兜底。

**Q：领料后纯查数追问断了**  
A：领料读链 Assigner **不要写** `data_analysis_conversation_id`（见 §5.6.5）。

**Q：纯查数误进 Agent**  
A：分类器 DATA 是否准确；Fast 链是否正常；领料是否在 Agent 前已 Fast 查库存。

**Q：还要不要 erp_login Tool？**  
A：Tool 保留在 Tools 列表供测试；**不要挂 Agent**。登录走画布。
