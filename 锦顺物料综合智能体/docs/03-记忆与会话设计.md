# 记忆与会话设计

## 1. 设计目标

1. **数据分析追问**：沿用现有 `last_query`、`origan_data_records`，避免重复查库
2. **领料多轮补全**：维护 `requisition_draft` 状态机，支持「改数量」「加一行」「确认提交」
3. **物料指代**：`last_material` 解析「这个 / 上面那个料」
4. **登录态**：`auth_token` + `user_profile`，全领料 Tool 共享
5. **可选长期记忆**：跨会话用户偏好（默认部门、常用物料）

---

## 2. Conversation Variables（Dify 会话变量）

### 2.1 沿用（来自现有 YAML）

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `last_query` | string | 用户上一轮完整问题（追问合并用） |
| `origan_data_records` | string | 原始查询结果 JSON/文本 |
| `data_records` | string | 处理后数据（分析/图表用） |

### 2.2 新增 — 认证

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `auth_token` | string | ERP `access_token`，**勿写入日志明文** |
| `token_expires_at` | string | ISO 时间或 Unix 时间戳，用于过期判断 |
| `user_profile` | object | 见下节 |

**user_profile 结构示例**：

```json
{
  "user_id": "U001",
  "username": "zhangsan",
  "name": "张三",
  "dept_id": "D001",
  "dept_name": "高精密事业部",
  "factory_id": "F001",
  "factory_name": "高精密事业部",
  "roles": ["material_request"]
}
```

### 2.3 新增 — 领料

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `requisition_draft` | object | 当前领料草稿（含 ERP draft_id） |
| `last_material` | object | 最近选中/检索的物料 |
| `intent_context` | object | 可选，当前任务上下文快照 |

**last_material 示例**：

```json
{
  "material_code": "M001234",
  "material_name": "阻焊油墨",
  "spec": "KB-6160",
  "unit": "KG",
  "stock_qty": 25,
  "factory": "高精密事业部"
}
```

**requisition_draft 示例**：

```json
{
  "status": "DRAFT",
  "draft_id": "DRAFT-001",
  "items": [
    {
      "material_code": "M001234",
      "material_name": "阻焊油墨",
      "quantity": 10,
      "unit": "KG"
    }
  ],
  "dept_id": "D001",
  "dept_name": "高精密事业部",
  "warehouse_id": "W001",
  "purpose": "生产补料",
  "remark": "",
  "missing_fields": []
}
```

## 3. 领料草稿状态机

```
                    ┌──────────────┐
                    │    (无)      │
                    └──────┬───────┘
                           │ 用户发起领料 / save_draft
                           ▼
                    ┌──────────────┐
         ┌─────────│    DRAFT     │─────────┐
         │         └──────┬───────┘         │
         │ 修改数量/物料   │ 用户「确认提交」  │ 用户「取消」
         │         ┌──────▼───────┐         │
         └────────►│PENDING_CONFIRM│         │
                   └──────┬───────┘         │
                          │ submit 成功      │
                          ▼                  ▼
                   ┌──────────────┐   ┌──────────────┐
                   │  SUBMITTED   │   │  (清空 draft) │
                   └──────┬───────┘   └──────────────┘
                          │ ERP 审批
              ┌───────────┼───────────┐
              ▼           ▼           ▼
        APPROVED    REJECTED    PENDING_APPROVAL
```

| 状态 | 含义 | Agent 行为 |
|------|------|------------|
| `DRAFT` | 信息未齐或待确认 | 可追问 missing_fields |
| `PENDING_CONFIRM` | 已展示确认卡片 | 仅响应确认/修改/取消 |
| `SUBMITTED` | 已提交 | 返回单号，清空 draft |
| `APPROVED` / `REJECTED` | 终态 | 通过 `erp_get_requisition` 查询 |

## 4. Token 生命周期

### 4.1 登录写入

`erp_login` 成功后，由 **Code 节点或 Assigner** 写入：

- `auth_token` ← `response.access_token`
- `token_expires_at` ← 当前时间 + `expires_in`
- `user_profile` ← `response.user`

### 4.2 过期处理

- 每次调用领料 Tool 前，Agent 提示词要求检查 token（或由 HTTP Tool 前置 Code 节点校验）
- 响应 `401` → 清空 `auth_token`，Final Answer：「登录已过期，请重新登录」

### 4.3 两种登录入口

| 方式 | 说明 |
|------|------|
| **对话内登录** | 用户发送「登录 工号 密码」，Agent 调 `erp_login` |
| **SSO 预注入（推荐）** | 嵌入页 / Start 节点传入 `sso_token`，首条消息跳过密码 |

**安全**：密码 **不得** 写入 conversation 变量；仅用于当轮 HTTP 请求体。

## 5. 数据分析记忆（沿用增强）

现有子工作流逻辑 **保持不变**：

1. **新查询**：保存 `last_query`，清空或覆盖 `origan_data_records`
2. **追问**：「历史数据充分性判定」→ 可以则直接分析，不可以则合并问题重新 SQL
3. **明细导出**：大数据量走 XLSX Tool

主 Agent 调用 `query_material_data` 后，子工作流仍负责更新 `origan_data_records`；主 Agent 可在 Observation 中读取摘要，并将关键物料写入 `last_material`（可选 Code 节点）。

---

## 6. 长期记忆（可选扩展）

Dify 会话变量 **不跨会话持久**。若需「记住默认事业部、常用物料」：

| 方案 | 说明 |
|------|------|
| Dify Memory 插件 | 若版本支持，存 user 级 key-value |
| ERP 用户偏好 API | `GET/PUT /api/user/preferences` |
| 外部 Redis / SQL | `user_id → preferences` |

初版 **可不做** 长期记忆，仅用 `user_profile` 默认值即可。

---

## 7. Assigner 节点配置要点

| 时机 | 操作 |
|------|------|
| 登录成功 | overwrite `auth_token`, `user_profile`, `token_expires_at` |
| save_draft 成功 | overwrite `requisition_draft` |
| submit 成功 | clear `requisition_draft`，可选写入 `last_requisition_no` |
| 新数据分析查询 | 子工作流内 overwrite `last_query`, `origan_data_records` |
| 401 | clear `auth_token` |
