## 2. 谁干什么（职责边界）

| | **主助手（综合 Chatflow）** | **子助手（数据分析子 Chatflow）** |
|--|---------------------------|----------------------------------|
| **判断** | 要不要 **查数** / **领料** / **寒暄** / **先查后领** | 要不要 **查询 vs 追问** |
| **传什么** | 用户 **原话** `query`；有则带 **子 conversation_id** | 自己用 id 读上一轮 SQL/明细 |
| **不做什么** | 不 Text2SQL、不分查询/追问、不重写表格 | 不管领料、不管主窗口登录 |

**结论**：主助手 **只分 4 类**；「提供明细」和「统计各月消耗」一样，都是 **DATA → Fast**，查询/追问交给子助手。

---

## 3. 四类意图（分类器配置）

| 类名 | 含义 | 走哪 | 示例 |
|------|------|------|------|
| **DATA** | 数据库 **统计、分析、明细、追问**（**不含 GON 单号查 ERP 状态**） | **Fast** | 「统计2025年各月消耗」「覆铜板3月用量」「**提供明细**」 |
| **CHITCHAT** | 寒暄、能力咨询 | **短 LLM** | 「你好」「你能做什么」 |
| **REQUISITION** | 领料/要料/申请；**GON 单号查状态/审批** | **领料子流程**（先 DATA Fast 读，再 Agent 写） | 「帮我领10KG油墨」「查询 GON…状态」 |
| **MIXED** | **同一句**里既要查又要领 | **领料子流程** | 「查油墨库存，够的话领10KG」 |

### If-Else 连线

| 条件 | 出口 |
|------|------|
| `class_name` = **DATA** | → **① DATA Fast**（纯查物料/库存/统计，**不进领料、不进 Agent**） |
| `class_name` = **CHITCHAT** | → 寒暄 LLM |
| **ELSE**（REQUISITION 或 MIXED） | → **领料子流程**（与 `use_requisition_flow=true` 汇合，**不是直进 Agent**） |

> **MIXED 必须保留**：一句里查+领，Fast 做不了，必须 Agent 多步 Tool。

分类器文案 → [`prompts/意图分类器-阶段3.5.md`](../prompts/意图分类器-阶段3.5.md)

**GON 查单双保险**（阶段 5 必配）：

1. Code [`detect_requisition_route.py`](../workflows/code/detect_requisition_route.py)：`use_requisition_flow=="true"` → **领料子流程**（含 **帮我领**、GON、确认提交）；**不是直进 Agent**
2. 分类器 REQUISITION 描述含 GON/领料单状态，DATA **排除** GON

```
登录路由 false → Code 领料/查单路由
  → use_agent == true → Agent（已登录兜底 If-Else 同阶段4）
  → false → 意图分类器 → …
```

发布前：`python3 workflows/code/test_detect_requisition_route.py`

## 4. conversation_id（两层 id）

| 名字 | 是什么 | 谁维护 | HTTP 传不传 |
|------|--------|--------|-------------|
| `sys.conversation_id` | **主窗口**会话 | Dify 自动 | ❌ ** never** |
| `data_analysis_conversation_id` | **子助手**一段查数对话 | 首问 API 返回 → **Assigner 写入** | 有则 ✅ 自动带上 |

**不是**「主窗口 id 传给子助手」，而是 **子助手自己返回的 id，存会话变量，下次有就带上**。

```
首问 DATA → Body 不带 id → 子助手返回 id → Assigner 存
再问 DATA（含「提供明细」）→ Body 自动带 id → 子助手自己判追问
```

**主助手不用判**「是不是追问」；**`build_chat_messages_body.py`** 负责：有 id 就写入 Body，没有就不写。

## 5. Fast 链（读路径 · DATA + 领料查库存）

**纯查数**与**领料查库存**共用同一套 Fast HTTP（子 Chatflow Text2SQL），**不经 Agent Tool**。

```
DATA 意图
  → Code「组装Chat请求」     query + data_analysis_conversation_id
  → HTTP POST http://nginx/v1/chat-messages
  → Code「解析SSE」           parse_sse_and_split.py
  → Assigner                  写 id / summary / detail
  → Answer                    {{#conversation.last_query_detail#}}

REQUISITION 意图（已登录）
  → 同上 Fast 链（question 可 Code 组装为查库存）
  → Assigner
  → Agent（仅 erp_* 写操作）
```

| 节点 | 要点 |
|------|------|
| HTTP URL | `http://nginx/v1/chat-messages`（勿用公网 IP，容器 hairpin 会挂） |
| Authorization | `Bearer app-NxITngK2xpaL1nGYMiQFYye5` |
| user | 固定 `fast-path-user`（首问追问相同） |
| query | 用户原话，不改写 |
| 展示顺序 | detail 内已排：**表格 → 要点速览 → ECharts** |

代码文件：

- [`build_chat_messages_body.py`](../workflows/code/build_chat_messages_body.py)
- [`parse_sse_and_split.py`](../workflows/code/parse_sse_and_split.py)

## 7. 会话变量

### 7.1 查数（阶段 3.5 · 3 个）

| 变量 | 写入时机 | 用途 |
|------|----------|------|
| `data_analysis_conversation_id` | 每次 Fast 成功后 | 下次 HTTP 自动带 id |
| `last_query_detail` | 同上 | Answer 展示（含表+分析+图） |
| `last_query_summary` | 同上 | 可选；Answer 只绑 detail 即可 |

### 7.2 登录（阶段 4 · 3 个）

| 变量 | 写入时机 | 用途 |
|------|----------|------|
| `auth_token` | 登录链 Assigner 成功时 | Agent 调 erp_* 鉴权（阶段 5） |
| `token_expires_at` | 同上 | 可选过期判断 |
| `user_profile` | 登录链 Assigner 成功时 | 默认部门、展示用户名 |
| `login_pending` | 未登录触达领料时写 `true`；登录成功清空 | 识别用户下一句自然回复的凭据 |

操作手册 → [18-阶段4-登录与会话变量操作手册.md](18-阶段4-登录与会话变量操作手册.md)（**被动登录**，不要求用户先说「我要登录」）

## 8. 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| SSRF blocked nginx | Chatflow HTTP 走 SSRF | 运维 NO_PROXY + nginx |
| 公网 IP max retries | 容器 hairpin | 用 nginx，勿用 120.238… |
| 400 | Body 带空 `conversation_id` | 用 `build_chat_messages_body` |
| 追问「未返回结果」 | 没带子 id 或 Assigner 未写 | 查首问 Assigner 是否有 uuid |
| 要点速览重复 | Answer 同时绑 summary+detail | 只绑 `last_query_detail` |
| ECharts loading | ` ```| ` 粘连 | 已修 parse_sse_and_split |
| 「提供明细」走 Agent | 分类器未并 DATA | 并成 DATA → Fast |
| **GON 查状态走查数** | 含「查询」被误判 DATA | 配 `detect_requisition_route` + 更新分类器 |
| **帮我领走查数** | 分类器误判 DATA；路由只拦 GON | 路由 Code 须含 **帮我领/确认提交** 等关键词 |
