## 总览：改造前后

| 项 | 阶段 3（过渡） | 阶段 3.5（目标） |
|----|----------------|------------------|
| 画布 | User → Agent → Answer | User → 分类器 → Fast / Agent 分支 |

## 步骤 1：升级网关 Workflow（约 15 分钟）

应用：`query_material_data_proxy`（发布 Tool 名 `query_material_data`）

### 1.1 替换 Code 节点「解析SSE」

1. 打开 Workflow → **解析SSE** Code 节点  
2. **全量替换**为 [`workflows/code/parse_sse_and_split.py`](../workflows/code/parse_sse_and_split.py) 中 `main` 及以上代码（Dify 只粘贴 `import` 到 `return` 部分）  
3. **输出变量** 增加并绑定：

| 输出变量 | 类型 |
|----------|------|
| `summary` | string |
| `detail` | string |
| `conversation_id` | string |
| `answer` | string（保留，兼容 Agent Tool） |

### 1.2 结束节点

| 输出字段 | 来源 |
|----------|------|
| `summary` | 解析SSE / summary |
| `detail` | 解析SSE / detail |
| `conversation_id` | 解析SSE / conversation_id |
| `answer` | 解析SSE / answer（可选） |

### 1.3 自测

| question | conversation_id | 期望 |
|----------|-----------------|------|
| `你好，请只回复两个字：收到` | 空 | summary/detail 含「收到」 |
| `查询2025年各分类物料入库数量` | 空 | detail 含表格；summary 为短导语 |

### 1.4 发布

1. **发布 → 发布更新**  
2. **发布 → 发布为工具**（刷新 Tool schema，Agent 若仍挂载需重新添加一次）

- [ ] 网关 Workflow 已输出 summary / detail / conversation_id  
- [ ] Tool 自测通过

## 步骤 6：Fast 查数分支（约 20 分钟）

> **锦顺现网**：`nginx` SSRF 拦截 + 公网 `workflows/run` max retries → **请用 §6B 直连 chat-messages**，勿再用 workflows/run。  
> 详述：[15-DATA_QUERY §12](15-DATA_QUERY-Fast查数路径配置详解.md#12-推荐fast-路径直连-chat-messages锦顺现网)

### 6A. workflows/run（仅当容器能访问该 URL 时用）

### 6.1 HTTP 请求节点「调用查数网关」

| 项 | 值 |
|----|-----|
| 方法 | POST |
| URL | `http://120.238.80.70:15657/v1/workflows/run`（**主 Chatflow 勿用 nginx**，会被 SSRF 拦截） |
| 连接/读取超时 | 600 / 3600 |

**Headers**

| Key | Value |
|-----|-------|
| Authorization | `Bearer <Workflow API Key>` |
| Content-Type | application/json |

**Body（JSON）**

```json
{
  "inputs": {
    "question": "{{#sys.query#}}",
    "conversation_id": "{{#conversation.data_analysis_conversation_id#}}"
  },
  "response_mode": "blocking",
  "user": "fast-path-user"
}
```

> `conversation_id` 首次为空字符串即可；Dify 变量为空时通常传 `""`。

### 6.2 Code 节点「解析网关响应」

粘贴 [`workflows/code/parse_workflow_run_response.py`](../workflows/code/parse_workflow_run_response.py)

**输入**：`raw` ← HTTP / body（或 text，以运行日志为准）

**输出**：`summary`、`detail`、`conversation_id`

### 6.3 Variable Assigner「写入查数会话」

| 变量 | 值 |
|------|-----|
| `conversation.data_analysis_conversation_id` | 解析网关响应 / conversation_id |
| `conversation.last_query_summary` | 解析网关响应 / summary |
| `conversation.last_query_detail` | 解析网关响应 / detail |

操作：**Overwrite**（覆盖写入）

### 6.4 直接回复「Fast Answer」

回复内容（**推荐：detail 已含 表格→要点速览→ECharts 顺序**）：

```
{{#conversation.last_query_detail#}}
```

若仍用双段模板，会重复要点速览，**勿再**同时输出 summary + detail。

- [ ] Fast 分支：HTTP → Code → Assigner → Answer 已连通  

### 6B. 直连 chat-messages（**锦顺现网推荐**）

替换 6A 的 HTTP + Code：

**HTTP**

| 项 | 值 |
|----|-----|
| URL | 先 `http://120.238.80.70:15657/v1/chat-messages`；仍 max retries → 运维 §13 后改 `http://nginx/v1/chat-messages` |
| Authorization | `Bearer app-NxITngK2xpaL1nGYMiQFYye5` |
| Body | `streaming` + `query` + `conversation_id`（见 15 文档 §12.1） |

**Code**：[`parse_sse_and_split.py`](../workflows/code/parse_sse_and_split.py)（**不是** parse_workflow_run_response）

Assigner / Fast Answer 与 6.3、6.4 相同。

## 常见问题

**Q：HTTP workflows/run 404**  
A：确认 URL 带端口 `:15657`；Key 对应当前 Workflow 应用。

**Q：SSRF blocked nginx / private network**  
A：主 Chatflow HTTP **不能**用 `http://nginx/...`。改用 `http://120.238.80.70:15657/v1/workflows/run`；若 timeout 见 [15 §12 直连 chat-messages](15-DATA_QUERY-Fast查数路径配置详解.md#12-备选直连-chat-messages绕过-workflowsrun) 或运维放行 Squid。

**Q：outputs 为空**  
A：检查网关 End 节点是否暴露 summary/detail；blocking 响应看 `data.outputs`。

**Q：追问仍像新问**  
A：查 Assigner 是否写入 id；Fast HTTP body 是否绑定 `conversation.data_analysis_conversation_id`。

**Q：Fast 仍慢**  
A：正常 ≈ Tool 17s + 分类 ~1s；若 >30s 看是否误走 Agent。

**Q：Agent 仍输出整表**  
A：换 [阶段 3.5 混合版 Instruction](../prompts/主控Agent系统提示词-阶段3.5混合版.md)；Answer 模板不要只绑 Agent.text。
