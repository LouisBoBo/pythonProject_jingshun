# 意图分类器 · 阶段 3.5（4 类 · 定稿）

> **节点**：主 Chatflow「锦顺物料综合助手」→ **问题分类器**  
> **模型**：Qwen3-4B 或 Qwen3-VL-30B，`temperature = 0`  
> **输入**：`{{#sys.query#}}`（或 User Input / query）  
> **说明**：查询 / 追问 **不在此区分**，统一归 **DATA**，由子助手内部分类。

---

## 分类列表（添加 4 个分类）

**名称必须与下表完全一致**（供 If-Else 绑定）。

### 1. DATA

**描述**：
```
凡涉及物料**数据库统计/分析**的查询：统计、排名、占比、趋势、采购、消耗、入库、出库、明细、展开、追问。示例：「统计2025年各月物料消耗金额」「查询覆铜板26年3月用量」「提供明细」「油墨库存多少（数据分析口径）」。

**明确不属于 DATA（归 REQUISITION → Agent）**：
- 领料单/出仓单 **GON** 号查状态、审批进度（如「查询 GON20260611003 状态」「GONxxx 到哪了」）
- 我的领料单、我的申请、审批到哪
- 领料、要料、出库申请（无统计/分析时）

含「查询」二字但对象是 **GON/领料单号** 的，**不是** DATA，不要走 Fast 查数。
```

### 2. CHITCHAT

**描述**：
```
寒暄、能力咨询、感谢、与查数领料无关的闲聊。示例：「你好」「你能做什么」「谢谢」「在吗」。
```

### 3. REQUISITION

**描述**：
```
领料、要料、出库申请、提交工单、申请物料；**以及 ERP 领料单/出仓单（GON 号）的状态与进度查询**。整句**没有**数据库统计/分析语义时归本类。

示例：
- 「帮我领 10KG 阻焊油墨」「申请领料」
- 「查询 GON20260611003 状态」「GON20260611003 到哪了」
- 「我最近的领料单」「审批到哪了」

**GON/DRAFT 单号 + 查状态/进度 → 必归 REQUISITION，禁止归 DATA。**
```

### 4. MIXED

**描述**：
```
同一句话里既有查数/查库存/分析，又有领料或申请；或「先…再…」「够的话帮我领」。示例：「查一下油墨库存，够的话领 10KG」「统计消耗最多的物料并帮我申请领 5 箱」。
```

## 系统提示词（可选 · Advanced / Instructions）

```
你是锦顺物料综合助手的路由器。只根据用户当前一句话输出唯一类别。
优先级（高→低）：
1. MIXED — 同句含统计/分析 + 领料/申请
2. REQUISITION — 领料/要料/申请；**GON或领料单号查状态/审批**；我的领料单
3. DATA — 数据库统计、分析、明细、提供明细（**不含 GON 单号查 ERP 状态**）
4. CHITCHAT — 寒暄与能力咨询

「查询 GON20260611003 状态」→ REQUISITION，不是 DATA。
禁止输出解释。
```

## If-Else 分支

| 分类 | 分支 |
|------|------|
| **DATA** | → **Fast 查数**（HTTP → 子助手 API） |
| **CHITCHAT** | → **短 LLM 寒暄** |
| **REQUISITION** | → **Agent** |
| **MIXED** | → **Agent** |

```
IF class_name = DATA      → Fast
ELIF class_name = CHITCHAT → LLM
ELSE                       → Agent（REQUISITION + MIXED）
```

## 与 conversation_id 的关系

- **DATA**（含「提供明细」）都走 **同一条 Fast 链**  
- HTTP Body 由 [`build_chat_messages_body.py`](../workflows/code/build_chat_messages_body.py) 组装：**会话里已有子 id 就带，没有就不带**  
- **子助手**根据 id + query 自己判查询/追问
